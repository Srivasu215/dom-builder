Runtime Pitfall 03

Component Type & Sub-Type

The type field is the central routing key that instructs the rendering pipeline which builder algorithm to dispatch. Mistyping the type or omitting the required sub-mode results in undefined builder dispatch errors.

The Story: The Missing Sub-Type Trap

In modern json-renderers (such as v19), tables support multiple structural variants: simple, withFooter, headerOnly, and bodyOnly. The dispatcher parses the type using dot notation: 

// Inside json-renderers v19 dispatcher:
if (config.type.includes(".")) {
  const parts = config.type.split(".");
  mainType = parts[0]; // "table"
  subType = parts[1];  // "simple"
}

If a developer passes plain type: "table", the sub-mode defaults to "table". Because the sub-builder table only contains simple, withFooter, etc., looking up builders["table"] yields undefined, triggering: 

TypeError: i is not a function at V (min.js:1019:46)

The table never mounts, leaving the user with an indefinite "Rendering table to DOM..." placeholder.

How the Guard Enforces Type Intent

Inside json-renderers-guard, validateType ensures the primary key is cleanly defined:

  • Presence Check: Rejects missing type keys with Error: Missing compulsory key: "type".
  • Type Verification: Ensures the value is a string with TypeError: type must be a string.
  • Sub-Type Convention: For table renderers, use "table.simple" to specify standard table generation.
❌ Bad Input 
// Plain "table" without sub-type
const badConfig = {
  type: "table", // 💥 Causes v19 builder lookup to fail
  targetHtmlId: "dom-container",
  data: [{ name: "Alice" }],
  columns: [{ columnName: "name" }]
};

render(badConfig);
// 💥 TypeError: i is not a function
✅ Good Input 
// Correct dot notation sub-type
const goodConfig = {
  type: "table.simple", // ✅ Clean dispatcher match
  targetHtmlId: "dom-container",
  data: [{ name: "Alice" }],
  columns: [{ columnName: "name" }],
  appendPosition: "replace",
  classToApply: "table table-striped"
};

guardFunc(goodConfig); // Returns true ✅
render(goodConfig);    // Builds & mounts cleanly ✅
Supported Type Catalog: Common valid types across the ecosystem include table.simple, table.withFooter, select, selectOptionsOnly, datalist, and form.
