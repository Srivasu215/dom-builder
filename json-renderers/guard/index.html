The Contract

A client sends a config object to describe the UI it wants. The json-renderers-guard repository defines and checks the expected input contract, helping clients discover missing or incorrectly shaped configuration before rendering is attempted.

01

What Is the Client Contract?

A contract is an agreement between the client code and the renderer about the shape of the input. The client supplies the expected fields; the guard checks whether the supplied configuration follows the supported rules.

Client sends

The config object, including the component type, data, columns, and target element ID.

Guard validates

It checks the configuration against the input rules defined by the guard's spec and mount checks.

Client gets guidance

If the input is invalid, the guard throws an error so the client can identify and fix the configuration problem.

Why this helps: The contract gives client developers a clear way to prepare valid input. The guard validates the input; it does not build the UI or guarantee that every later rendering operation will succeed.
02

Understand the Configuration

These are the six main keys shown in this example. Together, they describe the client's request and form part of the input contract checked by the guard.

1. type

The component to render. Example: "table.simple" asks for a simple table.

2. data

The records that will appear as rows. Here, data comes from batches.json.

3. columns

Defines which data fields become table columns, using columnName.

4. targetHtmlId

The ID of the HTML element where the renderer should place the output. The element must exist in the page.

5. appendPosition

A setting that controls how output is placed in relation to the target. Use a value supported by your renderer version.

6. classToApply

CSS class name(s) to apply to the rendered output, depending on the renderer's supported options.

Important: The guard checks the configuration contract. It does not create the table itself. If the guard accepts the config, the renderer can then try to build the UI.
03

Example: The Configuration Object

This is the config used to request a table showing item names and base units. Click Copy code to copy just this example.

JavaScript · config object
const config = {
  type: "table.simple",
  targetHtmlId: "dom-render-container",
  data: data.slice(0, 50),
  columns: [
    { columnName: "itemName" },
    { columnName: "baseUnit" }
  ],
  appendPosition: "",
  classToApply: "",
  showLog: true
};

In this example, data.slice(0, 50) selects up to the first 50 records. The two column definitions tell the table to show itemName and baseUnit.

04

How the Config Is Used

The guard is called before the renderer, so invalid configuration can be reported before rendering is attempted.

1. Prepare data

Load product or batch records from batches.json.

2. Build config

Choose the component, target element, records, and columns.

3. Check config

guardFunc(config) checks the expected input format.

4. Render table

If the guard does not throw, call render(config).

JavaScript · guard then render
try {
  guardFunc(config); // Check the configuration first
  render(config);    // Continue to render if the check passes
} catch (err) {
  console.error("Validation / Render error:", err);
}
