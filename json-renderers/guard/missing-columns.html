Runtime Pitfall 04

Column Schema Contract

In structured table rendering, columns define both data mapping and visual presentation. Passing plain strings instead of column objects violates the contract and crashes cell builders.

The Story: Strings vs. Column Objects

In older renderers (like v14), a simple array of string names was often accepted: columns: ["name", "unit"]. However, modern table builders (like v19) construct complex headers, column groups, cell templates, and custom widths: 

// Inside json-renderers v19 column loop:
for (let u = 0; u < inColumns.length; u++) {
  const d = inColumns[u];
  if (!d || typeof d != "object")
    throw new TypeError(`inColumns[${u}] must be an object`);
  if (typeof d.columnName != "string" || !d.columnName.trim())
    throw new TypeError(`inColumns[${u}].columnName must be a non-empty string`);
}

If client code passes strings (["itemName", "baseUnit"]), the engine halts with: 

TypeError: inColumns[0] must be an object

The Standard Column Fields

Every column object has a required identity and optional layout attributes:

Field Status Type Purpose
columnName Required Non-empty string Identifies the data key in row objects (e.g. "itemName").
width Optional string Sets column width for colgroup (e.g. "180px" or "25%").
template Optional object Customizes header/body/footer cell rendering templates.
❌ Bad Input 
// Plain strings instead of objects
const badConfig = {
  type: "table.simple",
  targetHtmlId: "dom-container",
  data: [{ itemName: "Steel Rods" }],
  columns: ["itemName"] // 💥 Strings reject in v19
};

render(badConfig);
// 💥 TypeError: inColumns[0] must be an object
✅ Good Input 
// Valid array of column objects
const goodConfig = {
  type: "table.simple",
  targetHtmlId: "dom-container",
  data: [{ itemName: "Steel Rods", baseUnit: "kgs" }],
  columns: [
    { columnName: "itemName", width: "200px" },
    { columnName: "baseUnit" }
  ],
  appendPosition: "replace",
  classToApply: "table table-striped"
};

guardFunc(goodConfig); // Returns true ✅
render(goodConfig);    // Renders table cleanly ✅
Fail-Fast Alignment: json-renderers-guard checks Array.isArray(columns) and enforces the existence of column definitions, ensuring zero corrupt column structures pass down to the builder.
