Runtime Pitfall 02

Null or Non-Array Data

Rendering tables and lists fundamentally requires an Array collection. Passing unhandled API failure payloads, single objects, or null values breaks downstream row loops.

The Story: The Unchecked API Response

In real-world applications, data is fetched asynchronously from backend endpoints: 

const response = await fetch("/api/items");
const payload = await response.json();

// If the API failed or returned 404, payload is { error: "Not Found" } instead of an Array!
render({
  type: "table.simple",
  targetHtmlId: "app",
  data: payload, // 💥 Not an Array!
  columns: [{ columnName: "itemName" }]
});

Without a guard check, downstream builder engines attempt data.map(...) or for (const row of data). The browser throws an unhandled TypeError: data.map is not a function, halting execution.

How the Guard Enforces Array Integrity

validateData in json-renderers-guard performs strict fail-fast validation:

  • Presence Check: If data === undefined, throws Error: Missing compulsory key: "data".
  • Array Type Verification: Evaluates Array.isArray(data). If false (e.g. string, object, or null), throws TypeError: data must be an Array.
❌ Bad Input 
// Object or Null passed instead of Array
const badConfig = {
  type: "table.simple",
  targetHtmlId: "dom-container",
  data: { error: "Resource Not Found" }, // 💥 Object
  columns: [{ columnName: "itemName" }]
};

guardFunc(badConfig);
// Throws: TypeError: data must be an Array
✅ Good Input 
// Valid array of row records
const goodConfig = {
  type: "table.simple",
  targetHtmlId: "dom-container",
  data: [
    { itemName: "0.09/30mm", baseUnit: "kgs" },
    { itemName: "0.11-25", baseUnit: "pcs" }
  ],
  columns: [
    { columnName: "itemName" },
    { columnName: "baseUnit" }
  ],
  appendPosition: "replace",
  classToApply: "table table-striped"
};

guardFunc(goodConfig); // Returns true ✅
Empty Arrays Are Allowed: If the API returns zero records (data: []), Array.isArray(data) passes, allowing the renderer to render an empty table state rather than crashing.
