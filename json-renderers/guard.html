json-renderers-guard

A simple story

The First Line of Defense: Schema & Runtime Validation

In dynamic, data-driven web applications, rendering calls frequently fail due to missing target IDs, undefined data arrays, or mistyped component names. json-renderers-guard is the lightweight sentinel that validates every render request before any DOM building begins — preventing silent crashes and saving hours of debugging.

Guard Purpose: Intercept every render request, check compulsory keys, confirm DOM target existence, and output actionable developer diagnostic warnings.
Why It Matters

The 4 common runtime pitfalls in DOM rendering

Without a dedicated guard layer, rendering libraries easily throw obscure browser exceptions like TypeError: Cannot read properties of null or silently fail to mount elements.

Pitfall 01

Missing Target Element

The developer passes targetHtmlId: "user-table", but the ID in the HTML is misspelled or hasn't been rendered yet. The guard catches this and warns you immediately.

Pitfall 02

Null or Non-Array Data

An API query returns null, an error object, or undefined. The guard ensures data is verified as an array before iterations begin.

Pitfall 03

Unsupported Component Type

Passing type: "tabl" instead of "table.simple". The guard inspects the type catalog and indicates valid choices.

Pitfall 04

Missing Columns in Tables

Table components require defined column mappings. The guard verifies column arrays or provides safe defaults inferred from data keys.

The Checklist

Compulsory keys and validation errors

When guardFunc(config) is invoked, it validates every compulsory key and throws an immediate, descriptive Error if any rule is violated:

Key Status Expected Type Error Thrown on Violation
type Compulsory string (e.g. "table.simple") Error: Missing compulsory key: "type"
TypeError: type must be a string
data Compulsory Array of row objects Error: Missing compulsory key: "data"
TypeError: data must be an Array
columns Compulsory Array of column objects Error: Missing compulsory key: "columns"
TypeError: columns must be an Array
targetHtmlId Compulsory Non-empty string Error: Missing compulsory key: "targetHtmlId"
Error: targetHtmlId must be a non-empty string
appendPosition Compulsory string (e.g. "replace") Error: Missing compulsory key: "appendPosition"
TypeError: appendPosition must be a string
classToApply Compulsory string (e.g. "table table-striped") Error: Missing compulsory key: "classToApply"
TypeError: classToApply must be a string
showLog Optional boolean TypeError: showLog must be a boolean
01

type validation

Must be a string. If omitted, throws Error: Missing compulsory key: "type". If non-string, throws TypeError: type must be a string. For table renderers (like v19), supply dotted subtypes like "table.simple" or "table.withFooter".

02

columns validation

Must be an Array. If omitted, throws Error: Missing compulsory key: "columns". If not an Array, throws TypeError: columns must be an Array. In table renderers, each item is a column object with columnName (e.g. [{ columnName: "itemName" }]).

03

data array integrity

Must be an Array. If omitted, throws Error: Missing compulsory key: "data". If not an Array, throws TypeError: data must be an Array.

04

targetHtmlId mount target

Must be a non-empty string. If omitted, throws Error: Missing compulsory key: "targetHtmlId". If empty or whitespace, throws Error: targetHtmlId must be a non-empty string.

05

appendPosition & classToApply

Mounting parameters must be strings (e.g. appendPosition: "replace", classToApply: "table table-striped"). Missing keys throw compulsory key errors.

Implementation & CDN

How to use guardFunc via CDN

Import json-renderers-guard directly in browser ES modules via jsDelivr CDN and validate the configuration before calling the renderer: 

// 1. Import guardFunc and renderer via CDN
import guardFunc, { guardSpec, guardMount } from "https://cdn.jsdelivr.net/npm/json-renderers-guard/+esm";
import render from "https://cdn.jsdelivr.net/gh/keshavsoft/json-renderers@main/docs/dist/v19/min.js";

const config = {
  type: "table.simple",
  targetHtmlId: "dom-render-container",
  data: [
    { itemName: "Item 01", baseUnit: "kgs" },
    { itemName: "Item 02", baseUnit: "pcs" }
  ],
  columns: [
    { columnName: "itemName" },
    { columnName: "baseUnit" }
  ],
  appendPosition: "replace",
  classToApply: "table table-striped",
  showLog: true
};

try {
  // 2. Validate configuration (throws descriptive error if anything is wrong/missing)
  guardFunc(config);

  // 3. Render cleanly to the DOM
  render(config);
} catch (err) {
  // Catches missing keys, invalid types, or malformed arrays
  console.error("Validation / Render error:", err.message);
}
Modular Guard

guardSpec(config)

Validates only data specification keys (type, data, columns, showLog). Ideal when you don't need DOM mount keys.

Modular Guard

guardMount(config)

Validates only DOM mounting keys (targetHtmlId, appendPosition, classToApply).

Composite Guard

guardFunc(config)

Complete pipeline validation: executes both guardSpec and guardMount in one call.

Fail-Fast Architecture: By throwing descriptive errors before DOM creation begins, json-renderers-guard prevents downstream crashes and pinpoint exact configuration mistakes immediately.
