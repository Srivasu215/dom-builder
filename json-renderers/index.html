json-renderers

A simple story

Where Data + Columns + Type Become Native DOM

json-renderers is the high-level browser DOM mounting runtime. When you want to render a dynamic component, you don't write manual HTML strings or endless createElement boilerplate. Instead, you describe your intent in JSON — and the runtime coordinates validation, headless specification building, and native DOM mounting.

The Mental Model: type (intent) + data (raw facts) + columns (the story about data) + targetHtmlId (where it mounts).

The Main Idea

Describe what you want to display

Imagine you have an array of records from a database or API. Building a production-ready table with aligned columns, row serial numbers, formatted currency, and footer totals requires writing hundreds of lines of imperative HTML code.

With json-renderers, you simply provide a declarative description. The runtime reads the inputs, coordinates with its internal build and guard engines, and renders pure native DOM into your specified container.

1. Data

Raw Business Facts

Plain array of objects directly from your backend or state. Zero styling, zero tags, zero markup.

[{ item: "Rope", qty: 25 }]
2. Columns

Story About The Data

Defines visible fields, sequencing, user-facing titles, numeric alignment, and automated summary totals.

["item", "qty", "amount"]
3. Type

The Component Intent

Specifies what UI element to construct: table.withFooter, datalist, select, or form.

type: "table.withFooter"
Architecture Story

How json-renderers is built

json-renderers does not try to do everything in a single monolithic script. It follows a clean, decoupled 3-tier pipeline where each layer has a single, well-defined responsibility:

┌─────────────────────────────────────────────────────────────┐ │ Step 1: Guard Layer (json-renderers-guard) │ │ • Validates compulsory keys: type, data, targetHtmlId │ │ • Inspects data types and prevents runtime crashes │ └──────────────────────────────┬──────────────────────────────┘ ▼ ┌─────────────────────────────────────────────────────────────┐ │ Step 2: Headless Builder (json-renderers-build) │ │ • Compiles Data + Columns into JSON tag specifications │ │ • Builds Tables, Datalists, Selects, and Forms headlessly │ └──────────────────────────────┬──────────────────────────────┘ ▼ ┌─────────────────────────────────────────────────────────────┐ │ Step 3: DOM Engine (json-to-tag) │ │ • Translates JSON tag tree into native DOM elements │ │ • Mounts final HTML node tree cleanly into targetHtmlId │ └─────────────────────────────────────────────────────────────┘
01

Validating the request with json-renderers-guard

Before allocating DOM nodes or performing calculations, the guard inspects the render configuration. It verifies that the target DOM container actually exists on the page, that data is a non-null array, and that the specified type is supported.

02

Constructing the JSON blueprint with json-renderers-build

The builder takes the validated inputs and translates them into an abstract JSON tag structure (specifying element names, classes, attributes, table headers, rows, and footer sums). It does this headlessly — without touching the DOM, allowing fast execution and testability.

03

Fast native mounting with json-to-tag

The JSON blueprint is passed to json-to-tag, which traverses the tree and instantiates real browser DOM nodes using native document.createElement. Finally, the subtree is mounted into the target element with zero string concatenation.

Live CDN Example

Render a table with a single function call

Include your target container in the HTML, import the standalone bundle via CDN, and pass your configuration: 

<!-- 1. Target Container Element in your HTML -->
<div id="my-table"></div>

<!-- 2. Single ES Module Import & Render -->
<script type="module">
  import render from "https://cdn.jsdelivr.net/gh/keshavsoft/json-renderers@main/docs/dist/v18/min.js";

  render({
    type: "table.withFooter",
    columns: ["item", "qty", "amount"],
    data: [
      { item: "High Tensile Rope", qty: 25, amount: 3000 },
      { item: "Agri Shading Net",  qty: 10, amount: 1250 },
      { item: "Drip Irrigation Pipe", qty: 50, amount: 4500 }
    ],
    targetHtmlId: "my-table"
  });
</script>
Field Breakdown:
• type: Tells the builder to construct a table with footer summary totals.
• columns: Names the columns in order: item, quantity, amount.
• data: The raw business rows.
• targetHtmlId: The ID of the HTML element where the table will be mounted.
