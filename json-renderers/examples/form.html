Why Use json-renderers Form Builds?

Building data filter toolbars and composite forms frequently involves wiring up multiple inputs, labels, buttons, and matching datalists. json-renderers streamlines this with declarative schemas:

1. Schema-Driven Generation

Declare your fields once in a JSON column configuration; input labels, names, and attributes are generated automatically.

2. Paired Search & Filter Triggers

Each composite input control includes an integrated trigger action to filter or query target datasets immediately.

3. Two-Way State Synchronization

Synchronize input changes directly with linked tables and datalists without writing custom event glue code.

4. Automated Layout & Consistency

Consistent, enterprise-grade field spacing, accessible ARIA attributes, and visual styling across your entire suite.

How to Build It (Step-by-Step)

Declare your column fields, configure target containers, and bind the composite form controls to query your data: 

<!-- Target Containers in HTML -->
<div id="form-container"></div>
<div id="table-container"></div>

<!-- ES Module Import & Form Rendering -->
<script type="module">
  import { Form, Table } 
    from "https://cdn.jsdelivr.net/gh/keshavsoft/json-to-dom-renderers/docs/dist/v12/min.js";

  const columns = [
    { key: "item", label: "Product Name" },
    { key: "category", label: "Category" },
    { key: "amount", label: "Amount (₹)", type: "number" }
  ];

  // Initialize and render composite form
  const form = new Form({
    inColumns: columns,
    inConfig: { body: { columns: ["item", "category"] } },
    inTargetContainerId: "form-container"
  });
  form.render();
</script>

Schema Parameters:

Key Type Required Description
inColumns Array<object> Yes Specifies field metadata including key, label, and data types.
inConfig.body.columns Array<string> Yes Specifies which columns from the schema to render as interactive input controls.
inTargetContainerId string Yes The DOM element id where the compiled input controls are mounted.
