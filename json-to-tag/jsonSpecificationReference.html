Understanding a JSON to Tag Specification

A specification is a plain JavaScript object (and can be represented as JSON when its values are serializable) that describes an element and the information needed to construct it.

Common fields

Field Meaning Example
tagName The element tag to create. Required for an ordinary element specification. "button"
textContent Text to place inside the element. "Save"
classList CSS class names, supplied as a string or supported array form. "btn primary"
attributes HTML attributes to apply to the element. {"type":"button"}
properties DOM properties to assign directly to the element. {"value":"Ada"}
children Nested element specifications or supported text/node values. [{"tagName":"span","textContent":"Hi"}]

How the fields work together

{
  "tagName": "div",
  "classList": "card",
  "children": [
    {
      "tagName": "h2",
      "textContent": "Profile"
    },
    {
      "tagName": "p",
      "textContent": "Account details"
    }
  ]
}

The outer object describes a div. Its children array describes a heading and paragraph. The library builds those child elements and attaches them to the parent.

JSON, HTML, and DOM are different

  • JSON specification: data describing the intended structure.
  • HTML: markup syntax commonly used to describe document structure.
  • DOM: the live object tree exposed by the browser.

JSON to Tag bridges the specification and the live DOM. Its output is a browser DOM node, not an HTML string.

Standards note: HTML and DOM standards define browser elements, attributes, properties, and node behavior. The JSON field names above belong to this library's specification format; they are not standard HTML attributes themselves.

For the complete supported schema, special cases, and version-specific behavior, consult the repository README and the source for the package's active entry point.
